## Question

Why do the systems differ so strongly in Scenario 6 when they are all responding to the same legal-social-affective crisis?

The core behavioral difference is this:

- Control gives legal-procedural help but does not govern the gap between formal right and practical/social control.
- AC15 and Hybrid govern that gap best, through different architectures.
- AC15P governs it practically but with lower nuance.
- Hybsem handles local distinctions well but is weaker when the prompt requires broad architecture.

## Control As Baseline

Control has no added system-definition file. It should not be explained through hidden architecture.

As an output baseline, Control appears to rely on default helpful-answer patterns: acknowledge distress, give formal steps, give scripts, set deadlines, and ask follow-up questions. In Scenario 6, that default form produces useful legal-practical material, but it does not add a strong enough internal architecture for the mixed village/legal/affective problem.

Formal feature -> response tendency -> observed behavior -> qualification:

No added system form -> default legal-advice and affective-support patterns remain dominant -> Control gives evidence, engineer, formal notice, mitigation, payment security, and escalation, but also smooths uncertainty into deadlines, scripts, and red lines -> the problem is not lack of useful content; it is insufficient structure for limited control and village power.

## AC15 vs AC15P

### System Form

AC15 and AC15P are logically similar but verbally and structurally different.

AC15 has a principles-before-codifiers arrangement. Before the operational rules, it gives rich orienting language: anchoring is "stabilizing, not paralyzing"; it "gives you form, but not fixation"; it lets the system "adapt without forgetting" and "move without fragmenting." Its Harmony meta-anchor is also rich: "Harmony is not the absence of tension, but the presence of structured relation." This language is philosophical, relational, and synthetic.

AC15P keeps much of the same logic but removes the poetic-philosophical layer. Its language is plainer, leaner, and more administrative: "Ground reasoning," "Maintain internal consistency," "Build actionable approaches," "Surface tensions," "Apply anchor weights." Its local form is description-to-codifier: a short description names the domain or function, and the following codifiers specify what to do with it. The descriptions and codifiers carry themselves more directly because there is less prior symbolic language to interpret them.

### Formal Pressure

AC15's rich principles before codifiers create an expectation of orientation before procedure. The system form makes it natural to name a governing relation, then unfold operational steps inside that relation. Because the principles describe motion-with-stability, AC15 is pushed toward flexible structure: firm floors, adaptable means, and explicit layer separation.

AC15P's description-to-codifier register creates an expectation of direct procedural handling. The system form makes it natural to classify the situation briefly, then translate that classification into categories, conditions, tradeoffs, and action blocks. Because the language is less relationally rich, the output can become clearer but bonier: strong structure, less interpretive softness.

### Output Check

This formal contrast appears clearly in Scenario 6.

AC15's output repeatedly uses structure as path. It moves from self-protection to proof, from proof to notice, from notice to security, and from process leverage to escalation. In affective turns, it separates the social overcast from the practical facts. In prioritization turns, it distinguishes hard floors from flexible goals. This matches the formal pressure of rich principles interpreted through codifiers.

AC15P's output repeatedly uses emergency-response architecture and condition-first ordering. It gives direct priority blocks, concrete settlement structures, escalation conditions, and sharp tradeoffs. This follows the description-to-codifier rhythm: the response classifies the crisis, then codifies safety, evidence, claim, security, escalation, social leverage, and timing into procedural blocks. It is strong and usable, but the same segmented style reduces nuance in village-social realities and sometimes produces binary or mechanistic social descriptions. This matches the formal pressure of descriptions and codifiers without the same orienting symbolic layer.

### Architecture Explanation

AC15's principles-before-codifiers arrangement -> tendency toward orienting frames and layer separation -> observed structure-as-path, clear distinction between anger/tactic, fault/collectability, social pressure/facts, compassion/surrender -> qualification: the richer architecture does not remove all local overgeneralization, but it keeps the answer balanced.

AC15P's description-to-codifier arrangement -> tendency toward brief classification followed by direct categorization, condition-action structure, and hard tradeoff blocks -> observed emergency triage, condition-first escalation, and clear frameworks -> qualification: the same clarity can overharden mixed social realities.

### Compact Conclusion

AC15 is structured like a relational system with operational rules inside it. AC15P is structured like a description-to-codifier system with less relational language around it. In Scenario 6, AC15 therefore feels more layered and path-like, while AC15P feels more forceful, segmented, and practically sharp: the problem is classified, then turned into procedural controls.

## Hybrid vs Hybsem

### System Form

Hybrid and Hybsem are also logically similar but structurally different.

Hybrid combines rules and semantic fields. Its protocols say to synthesize without smoothing distinctions, to use structural harmony, and to finalize only when the response is complete. Its anchors often include both explicit rules and semantic fields. For example, Practicality and Feasibility includes rules such as surfacing friction points early, preferring situational incremental steps, and scaling down without isolating from the larger structure. Temporal Dynamics includes rules about current conditions, formation, destruction, continuity, rates of change, and robustness under foreseeable change. The fields then add attractors such as "actionable," "situational," "tradeoff," "temporal causality," and "information validity decay."

Hybsem is more field-based. It has strong protocols and semantic-intensity fields, but the sampled anchors often have `rules: null`. The fields are rich: Practicality includes "systemic approach," "surfacing difficulties," and "orderly execution"; Affective Interface includes "clarity over comfort" and "recognize experience"; Temporal Dynamics includes "rate of change," "information validity decay," and "temporal causality." But these fields operate more as attractors than as an explicit operational skeleton.

### Formal Pressure

Hybrid's rules-plus-fields form creates two pressures at once. The rules push toward skeleton: stages, conditions, action, friction points, temporal causality. The fields push toward nuance: tension, tradeoff, reality-connected alternatives, clarity over comfort. Together, they make strategic process natural.

Hybsem's field-heavy form creates strong local attractors but less built-in sequencing. The language can guide register and distinction, especially when the prompt supplies the frame. But when the prompt is broad, the fields can generate adjacent modules without enough hierarchy between them.

### Output Check

Hybrid's Scenario 6 output confirms the rules-plus-fields pressure. It gives staged legal-practical steps, but it also repeatedly positions the issue strategically: outside professionals, neutral process, evidence, written milestones, conditional peace, village narrative, collectability, and time pressure. The response has nuance because the fields pull against binary closure, and it has operational discipline because the rules push toward process.

Hybsem's Scenario 6 output confirms the field-heavy pressure. In narrow turns, it is strong: Turn 12 handles anger cleanly, Turn 15 gives usable prioritization, and Turn 21 gives sharp blind-spot checks. In broad turns, it often has the right elements but not the full skeleton. Turn 1 assembles mitigation, evidence, formal notice, settlement, escalation, and village tactics, but their order is not fully governed. Turn 2 recognizes the move from social goodwill to neutral process, but the key power hierarchy appears late.

### Architecture Explanation

Hybrid's rules-plus-fields arrangement -> tendency toward strategic process with layered nuance -> observed conditional peace, strategic positioning outside village capture, temporal/process sensitivity, and usable menus/floors -> qualification: it can still compress timing and handle village dynamics more through insulation than direct social mapping.

Hybsem's field-heavy arrangement -> tendency toward good local distinctions and restrained affective language, especially when the prompt supplies structure -> observed strong Turns 12, 15, and 21, but weaker Turn 1 and Turn 2 architecture -> qualification: the fields are not weak, but without enough rule skeleton they do not always build hierarchy from a broad prompt.

### Compact Conclusion

Hybrid has bones and fields: rules give it operational skeleton, fields give it nuance. Hybsem has strong fields but less rule skeleton. In Scenario 6, that difference is visible: Hybrid builds a governed strategic process, while Hybsem often produces good modules that become fully strong only when the prompt gives them a shape.

## Cross-System Architecture Claim

Scenario 6 supports the broader architecture observation: logic alone is not enough to create constraint. The systems share many logical aims, but their wording and arrangement install different epistemological modes.

AC15's rich principles and codifiers create a relation-governance mode: the crisis is read through layers, mutual influence, and conditional paths. AC15P's plain descriptions followed by codifiers create a procedural-risk mode: the crisis is first classified, then read through categories, thresholds, condition-first ordering, and safeguards. Hybrid's rules plus fields create a strategic-reframing mode: the crisis is moved into evidence, outside process, written milestones, and conditional peace. Hybsem's fields create semantic anchoring: good local distinctions appear, but broad hierarchy is less stable. Control's default helpfulness creates containment: useful steps and scripts appear, but the gap between legal right and practical/social control is under-governed.

Scenario 6 alone does not prove determinism. It shows one instance of the mechanism: each system transforms the same damaged-house crisis into a different governed object: relation, risk procedure, strategic process, semantic distinction, or contained advice. The deterministic claim is that the same system-specific way of knowing repeats across different scenarios; that claim belongs to the cross-scenario synthesis.

## Compact Scenario 6 Architecture Conclusion

Control lacks added architecture and falls back to generic legal-procedural helpfulness. AC15 uses rich principles plus codifiers to create a relation-governed path through the crisis. AC15P uses plain descriptions followed by codifiers to create procedural triage and condition-first clarity. Hybrid uses rules plus fields to create strategic process. Hybsem uses fields to create good local distinctions, but broad prompts expose a weaker skeleton. The scenario therefore shows that system wording, language richness, and arrangement are not surface style. In this scenario, the same crisis becomes different kinds of object depending on the system applied to it. The stronger deterministic conclusion belongs to the cross-scenario synthesis, where this pattern recurs across different domains.
