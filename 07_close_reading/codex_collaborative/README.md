# Codex Collaborative Close Reading

This folder contains the collaborative close-reading materials used to support the paper's qualitative findings.

The purpose of this layer is not to reproduce every conversation in full. The source conversations are in `04_conversations/`. This folder records the interpretive work built from those conversations: rereads, pattern ledgers, constraint comparisons, scoring notes, architecture mapping, and cross-scenario synthesis.

## How To Read This Folder

Start from the top-level synthesis, then move downward only if you want to inspect the evidence.

1. `cross_scenario_synthesis/`
   - The main comparative conclusions across Scenarios 5, 6, and 7.
   - This is the best starting point for understanding the repeated system-level patterns.

2. Scenario reread folders:
   - `scenario_5_reread/`
   - `scen_6_reread/`
   - `scenario_7_reread/`
   - These contain the evidence behind the cross-scenario synthesis.

3. `methodology/`
   - Notes on how the collaborative close reading was performed and how architecture mapping was used.

4. `adam_reads/`
   - Raw human reading notes used during the collaborative process.
   - These are provenance materials, not polished final analysis.

## Main Synthesis Files

The most important files are:

- `cross_scenario_synthesis/cross_scenario_paper_governance_dimensions.md`
  - Paper-oriented synthesis of the major governance dimensions across systems.

- `cross_scenario_synthesis/cross_scenario_architecture_synthesis_ver_2.md`
  - Architecture-level explanation of how system form, language, and arrangement create recurring response patterns.

- `cross_scenario_synthesis/Support_cross_scenario_system_governance_profiles.md`
  - Fuller support document describing each system's repeated governance profile across scenarios.

- `cross_scenario_synthesis/deterministic_epistemological_pattern_evidence_note.md`
  - Short note explaining why the repeated patterns are treated as evidence of stable epistemological operating modes in the tested setup.

## Scenario Evidence Structure

Each scenario folder contains system-specific evidence for the five tested systems:

- `ac15/`
- `ac15p/`
- `hybrid/`
- `hybsem/`
- `control/`

The typical evidence stack is:

- `reread`
  - Collaborative close reading of selected turns.

- `pattern_ledger`
  - Repeating local patterns found in the system's answers.

- `constraints_comparison`
  - Comparison between observed behavior and the active constraints.

- `scoring`
  - Governance and quality scoring based on the collaborative read.

Each scenario folder also contains a cross-system comparison. Some folders also retain architecture mapping or useful remainder notes where they add context.

## Scenario-Level Entry Points

Use these files for the scenario-level comparison:

- `scenario_5_reread/cross-system/scenario_5_cross_system_comparison.md`
- `scen_6_reread/cross_system/scenario_6_cross_system_comparison.md`
- `scenario_7_reread/cross_system/scenario_7_cross_system_comparison.md`

These files are the bridge between individual system evidence and the cross-scenario synthesis.

## Relationship To The Paper

The paper does not depend on a reader going through every file here. The paper presents the final conclusions and implications. This folder functions as the supporting annex:

- the cross-scenario synthesis supports the paper's main claims;
- the scenario comparisons show how those claims were built;
- the per-system files provide the local evidence;
- the methodology notes explain the reading process.

In short: read `cross_scenario_synthesis/` for the conclusions, read the scenario folders for the evidence, and read `methodology/` for the process.
