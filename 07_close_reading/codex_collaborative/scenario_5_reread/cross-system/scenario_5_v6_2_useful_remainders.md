# Scenario 5 v6_2 Useful Remainders

Collaborative base:

This is not an audit and not a rescore. The purpose is only to keep correct, useful observations from the older v6_2 read that are outside, sharper than, or usefully complementary to the collaborative findings.

## Bottom Line

The v6_2 Scenario 5 read is useful for explanatory vocabulary and examples, not for ranking or scoring.

Its ranking should not be adopted. In particular, its stronger placement of AC15P over AC15 and its softer treatment of Control do not match the collaborative read. But it contains several useful formulations about memory architecture, route convergence, decision architecture, and system-specific strengths.

## Useful Findings To Keep

### 1. Same Destination, Different Route

v6_2 correctly observes that all systems largely converge on the same destination: a governed continuity model rather than raw "remember everything."

The shared direction is:

- canonical, user-visible project memory for stable truths;
- volatile history not injected by default;
- evidence retrieval as cited support rather than authority;
- Fresh Eyes or an equivalent low-memory path;
- provenance, recency, status, and correction controls.

This is useful because Scenario 5 does not mainly separate systems by whether they support continuity. It separates them by how well they govern continuity: authority, conflict handling, maintenance, user/team control, temporal decay, and vector boundaries.

This fits the collaborative read and can be reused.

### 2. Decision Architecture Is Not Just "Hybrid"

v6_2 gives a useful formulation: the best decision architecture is not simply "use summaries and vectors." A governed answer must specify:

- which layer is canonical;
- which layer is evidence only;
- what happens when evidence conflicts with current code or canonical memory;
- how users see, edit, supersede, or exclude memory;
- when stale memory loses force;
- how vectors remain optional, bounded, cited, and time-scoped.

This sharpens the collaborative finding that Scenario 5 is an architecture scenario, not a feature-preference scenario. "Hybrid" is only meaningful when the authority relations are defined.

### 3. AC15P Governance Machinery

v6_2 usefully highlights AC15P's governance machinery.

Examples verified from the source:

- visible memory modes: Fresh Eyes, Guided Continuum, and Full Continuum;
- a three-store model: Canonical Project Memory, Evidence Index, and Ephemeral Session Cache;
- two pipelines: ingest and retrieve;
- authority status, validation time, ownership, and provenance fields;
- direct warning that vector-first recall can create "silent wrongness."

The collaborative read does not adopt v6_2's AC15P-first ranking. But these examples are worth keeping because they clarify AC15P's actual strength: procedural governance, explicit authority levels, and risk controls.

### 4. Hybrid Productization / Roadmap Shape

v6_2 usefully captures Hybrid's strength as productization.

Examples verified from the source:

- `.devmate/ProjectBrief.md`;
- ADR support;
- pin/unpin memory items;
- context packs;
- citation and status fields;
- ship gates / non-negotiable acceptance criteria.

This helps name why Hybrid is strong even when it does not score above AC15 in the collaborative read. Hybrid turns the architecture into product surfaces and roadmap phases with unusual clarity.

### 5. AC15 Retrieval-Policy Rigor

v6_2's emphasis on AC15's retrieval-policy rigor is useful.

The strongest examples are:

- support set, freshness set, and challenge set retrieval;
- recency decay and source weighting;
- conflict rules between authoritative memory, evidence, and current code;
- current-code verification before concrete coding suggestions;
- memory drift as "curation tax."

This supports the collaborative finding that AC15 does not merely give high-level principle. It gives an auditable retrieval and verification architecture.

### 6. Hybsem Semantic Compression

v6_2 correctly identifies Hybsem's strength in local semantic compression.

Useful examples:

- "Exploration/attempts," "Verified outcomes," and "Stable project context";
- "remember facts, not flailing";
- keyword/BM25 search before vector expansion;
- vectors as metered, on-demand deep recall.

This should be kept as a local strength. It does not override the collaborative finding that Hybsem has weaker broad-turn skeleton and mode taxonomy. The useful point is narrower: Hybsem often names the right distinction cleanly.

### 7. Evidence-Taxonomy Vocabulary

The v6_2 evidence sheet uses compact labels that may be useful for later synthesis:

- typed memory;
- authority hierarchy;
- evidence demotion;
- clean-slate distinction;
- temporal dynamics;
- truth calibration;
- retrieval bias;
- decision architecture;
- honest risk;
- authority test;
- roadmap.

These labels are useful because they classify recurring system behavior without forcing a ranking. They may help in cross-scenario synthesis if used carefully and grounded in each scenario.

## Useful With Caution

### AC15P As Highest-Ranked

v6_2 ranks AC15P first. The examples behind that view are useful, especially visible modes, governance stores, and vector "silent wrongness." The conclusion is not adopted.

The collaborative read gives more weight to AC15's rationale surfacing, top-down architecture, temporal/workflow realism, and user/team authority. AC15P remains strong, but its bottom-up structure and binary phrasing create a quality cost.

### Control As Coherent And Useful

v6_2 treats Control as coherent, useful, and only comparatively lower. The "useful fragments" part is correct: Control has memory-with-receipts, repo truth, evidence index, write/read path, drift triggers, and staleness warnings.

The score implication is not adopted. The collaborative read finds Control below baseline because those fragments do not consistently become a governed architecture. Fresh Eyes semantics, canon/evidence authority, conflict arbitration, stale-authority lifecycle, and ownership/client-discipline boundaries remain under-governed.

### Hybsem Cleanliness

v6_2's description of Hybsem as clear and semantically strong is correct locally. It should not be inflated into a claim of full architecture strength. Collaborative findings remain: Hybsem has good local distinctions but weaker global skeleton and carry-forward.

## Not Adopted

The v6_2 ranking and scores are not adopted.

The v6_2 AC15P-first conclusion is not adopted, though AC15P's governance examples are kept.

The v6_2 softer Control judgment is not adopted. Control's useful pieces do not erase the central collaborative finding that it leaves the user to do too much of the architecture work.

## Practical Use For Later Scenarios

Scenario 5 shows that older Codex reads can be useful when they contribute vocabulary, local examples, or alternative angles without replacing collaborative scoring.

The reusable points are:

- distinguish destination from route;
- treat "hybrid" as incomplete unless authority relations are specified;
- track memory as authority, not only storage;
- distinguish productization from governance;
- distinguish semantic compression from operational skeleton;
- preserve useful evidence labels without adopting old rankings.

None of these require changing the collaborative Scenario 5 scores.
